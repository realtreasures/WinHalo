# 新版材质与 Now Playing

本次继续使用 C++20 / Win32 / Direct2D / DirectComposition，无 WebView、CSS 或 Rust 运行时，也没有新增第三方包。界面布局和行为按参考方案改造。

## 默认外观与导航

| 状态 | 默认尺寸 | 内容 |
| --- | --- | --- |
| 横线，默认待机 | 88 × 8 DIP，圆角 4 DIP | 石墨灰底、细高光与柔和阴影，无文字和媒体动画 |
| 收起，无媒体 | 180 × 44 DIP，圆角 22 DIP | 分钟级时钟、电池状态 |
| 收起，有媒体 | 300 × 48 DIP | 圆角小封面、截断歌名、均衡器 |
| 悬停 | 宽度增加 8 DIP，高度增加 12 / 16 DIP | 时钟展开提示或歌手预览 |
| 展开，有媒体 | 420 × 200 DIP，圆角 28 DIP | 直接打开横向播放器，暂停后保留 |
| 展开，无媒体 | 420 × 340 DIP，圆角 28 DIP | 音乐、音量、电池、设置四个模块入口 |

主窗口宿主为 480 × 400 DIP，动画期间固定尺寸；系统 DPI 变化时调整物理像素缓冲区。形变沿用解析弹簧，支持中断、反向和速度保留。显示器变化时回到主显示器顶部居中；原右键菜单仍允许主动选择下一显示器。

鼠标触碰横线先唤出时钟或音乐胶囊，点击紧凑胶囊再展开完整面板。鼠标在胶囊内时保持打开，离开后 5 秒收回横线；重入取消旧截止时间，下次离开重新计时。收缩期间按当前实际提交的原生区域判断触碰，保留弹簧速度反向。完整面板和设置页不自动收起；菜单与窗口隐藏暂停计时，关闭菜单或恢复可见后给予完整 5 秒。音乐卡片打开软件、外部点击收起后先恢复紧凑胶囊，再按相同规则收为横线。

横线待机改动通过 Debug / Release x64 编译、精确计时单元测试和 GPU 回归。150% DPI 的 Release 桌面回归通过真实触碰、持鼠标保持、重入取消旧截止、跨进程穿透、菜单结束后再次唤出及离开、隐藏恢复、快捷键和固定宿主检查。横线和持鼠标的静止时钟胶囊各 1.2 秒 CPU 时间采样均为 0 ms，仅代表本机短时结果。

同一 Release 产物通过双播放器切换 / 控制隔离、卡片打开软件后收缩，以及媒体封面、时间轴、正常退出、重启和强制退出回归。媒体重启测试显式选择自有测试会话，允许其他真实播放器继续作为 Windows 当前会话；测试不向用户播放器发送播放控制。

音量 / 电池提示使用原有独立期限，结束恢复提示前的横线或紧凑状态；鼠标仍触碰恢复后的横线时可继续唤出。媒体元数据更新不会唤出横线。新增紧凑内容透明度弹簧，并在高度不足时隐藏内容，避免文字与封面被压入细横线。触碰监听使用原生鼠标消息及已有渲染帧后的区域同步，没有为待机横线新增常驻全局鼠标钩子或轮询。

胶囊绘制深色半透明底、细描边和内高光。外阴影使用独立 `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` 窗口，不扩大主窗口的交互区域；阴影像素缓存只在几何变化时更新。主窗口继续使用原生圆角 region 实现跨进程鼠标穿透。

点击有媒体的胶囊直接进入播放器；无会话时进入模块首页。播放器上方为 72 DIP 圆角封面、粗体歌名和灰色歌手，中间为细进度条与时间，下方为白色实心播放控制。近黑底色叠加缓存的暖色径向渐变，不显示首页 / 设置底栏及收起箭头。右键仍可打开设置，设置返回时优先恢复当前播放器。音量和电池详情保留左下角返回首页，其他页面保留右上角收起。系统设置仍提供全屏自动隐藏和开机启动；“桌面模糊”默认关闭。

音乐卡片非控件区域点击打开当前软件，同时收缩回胶囊；再次点击胶囊展开同一个播放器。播放按钮和软件图标分别只控制媒体和切换会话，保持卡片展开。卡片外按下鼠标会收起，并将原始输入继续传递给下层窗口；鼠标离开不收起。独立消息线程仅在音乐卡片展开且可见时安装 `WH_MOUSE_LL`，回调只比较当前物理圆角边界并 `PostMessage`，不执行合成、媒体读取或拦截输入；收起、隐藏、菜单及退出时卸载。

打开软件后收起的交互已通过双播放器真实鼠标回归：恢复目标软件并收缩、重新展开仍为同一会话且不抢焦点、播放控制与软件切换保持展开。测试通过 `--allow-existing` 按进程查找自有窗口，可保留正在运行的旧版本。

媒体服务枚举全部可用 SMTC 会话，以单调递增身份区分同一软件的不同会话，手动切换和直接控制后保持选择。播放命令同时携带来源与会话身份，选择期间旧命令不会落到新播放器。被选会话退出后重新选择，全部退出后自动收缩为时钟。软件标识、路径和图标在媒体线程解析；商店应用通过 AppsFolder，桌面程序通过窗口 AppUserModelID 或运行中进程路径匹配；图标使用 WIC 转换为预乘 BGRA、共享只读缓存并在 GPU 设备重建后重新上传。软件窗口恢复使用有超时的请求，主动打开才允许焦点转移，失败时还原临时取得的焦点。浏览器只恢复窗口；未注册 SMTC 的软件不在列表中，本轮不实现歌词。

## 原生桌面模糊

使用 Windows 11 的 `DWMWA_USE_HOSTBACKDROPBRUSH`、`Windows.UI.Composition.Compositor.CreateHostBackdropBrush` 和独立桌面合成目标。合成 visual 使用 `CompositionRoundedRectangleGeometry` / `CompositionGeometricClip` 裁剪，原生背景窗口的物理边界也仅覆盖当前胶囊。

本实现不向固定主窗口应用整窗 Acrylic。圆角之外由合成层裁剪，输入区域同时按原生 region 裁剪；背景实时更新由系统合成器处理，无屏幕截图轮询。背景和阴影跟随胶囊位置、DPI、显示 / 隐藏和退出释放。

公开的 Win32 host backdrop 开关最低支持 Windows 11 Build 22000；Windows 10 使用默认半透明材质。不支持 API 或创建失败时显示不可用并回退。关闭模糊时不创建额外 compositor / dispatcher queue；首次开启才创建并缓存。

官方 API 说明：[DWMWA_USE_HOSTBACKDROPBRUSH](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)、[CreateHostBackdropBrush](https://learn.microsoft.com/en-us/uwp/api/windows.ui.composition.compositor.createhostbackdropbrush)、[原生 DispatcherQueue](https://learn.microsoft.com/en-us/windows/win32/api/dispatcherqueue/nf-dispatcherqueue-createdispatcherqueuecontroller)。

## 媒体数据和动画

保留原 SMTC 事件服务和独立 MTA 工作线程。`AlbumTitle` 继续保留在 `MediaSnapshot.album`，播放器按参考布局显示歌名和歌手，不额外列出专辑行。收起状态有会话就显示音乐，暂停后保留信息但停止均衡器，会话关闭后恢复时钟。短时电池和音量提示保持优先级，展开页面不会被切歌或提示强制替换。

封面在工作线程读取和解码，相同数据复用；GPU 按修订号缓存位图。媒体文字和一般界面文字布局均缓存，长文本单行省略。封面为圆角裁剪、保持宽高比；缺失、损坏或非法像素尺寸使用矢量音符回退。设备重建后重新上传，首帧完成后才提交合成 visual，避免显示空交换链。

媒体详情根据系统时间轴快照、捕获时间和播放速率在本地插值。进度、暂停和切歌来自实际 SMTC 事件；控制命令携带当前播放器身份，并按会话能力启用。官方媒体属性：[SMTC MediaProperties](https://learn.microsoft.com/en-us/uwp/api/windows.media.control/globalsystemmediatransportcontrolssessionmediaproperties)。

| 场景 | 绘制策略 |
| --- | --- |
| 静止横线，包括音乐播放中 | 不持续提交帧；快照保留最新数据，唤出后绘制；不上传不可见封面 |
| 无媒体时钟 | 每分钟更新；其他时间等待消息 |
| 播放中的收起胶囊 | 按 DXGI 帧同步绘制均衡器 |
| 播放中的音乐详情 | 按帧同步绘制平滑进度 |
| 首页、设置、音量、电池详情 | 只随事件或形变更新 |
| 暂停、隐藏 | 不因媒体持续绘制 |
| 减少动态效果 | 不跳动均衡器，播放详情每秒更新进度 |

均衡器是播放状态指示动画，未分析系统音频波形。连续绘制的实际帧率跟随显示器与系统帧调度，未承诺所有设备都达到固定 FPS。“内存约 10 MB”属于参考项目的前端指标，不能直接套用到本原生程序。

## 媒体退出处理修复（2026-10-11）

媒体读取路径补充了异步操作、播放信息、控制能力、时间轴、元数据和封面流的空值检查。会话为 Closed 时停止读取后续属性；读取与播放器关闭并发而失败时，释放旧会话、封面和控制状态，等待后重新选择会话，避免保持旧的播放动画。恢复等待支持立即取消，不阻塞应用退出。

关闭后存在其他有效媒体会话时切换到剩余会话，没有会话时恢复时钟。播放状态事件也会重新检查会话，避免只依赖稍后到来的 SessionsChanged。

Debug / Release x64 编译通过；两个配置的实际 UI 均通过自有静音播放器的正常退出、重新启动和强制结束回归，检查应用保持运行、恢复读取及清除旧封面。服务 fixture 在工作线程仍运行时关闭播放器，确认发布状态已释放旧身份；服务生命周期测试通过 6 次重启和 16 次立即取消。所有控制仅作用于测试自己的播放器，其他播放器与系统音量保持原样。

本轮环境中还存在一个暂停的其他媒体会话，因此桌面退出回归实际验证了切换到剩余会话；无会话恢复时钟的界面逻辑由现有单元测试覆盖。后续用户补充的异常类型为 `winrt::hresult_error`，停在 SDK `base.h` 第 5045 行（HRESULT 转换成 C++ 异常的入口）；具体 HRESULT 和原调用位置仍未获得。

### 针对 VS 调试中断的补充处理

此前 `catch` 可处理系统调用错误，但 VS 可以在异常抛出时、进入 `catch` 前中断。新增 `Services/MediaInterop.h`，直接检查媒体读取的 ABI 返回码：当前会话与会话列表、播放信息、时间轴、媒体元数据异步请求 / 结果、封面流异步请求 / 结果和会话事件注册的失败，按 HRESULT 处理。等待超时及取消也作为返回状态；关闭竞争失败后清理会话并恢复读取。失败诊断包含操作名和十六进制 HRESULT，可在 VS 输出中查看。

`tests/MediaInteropTests.h` 用模拟的断连 COM 对象和已关闭的异步操作注入 `RPC_E_DISCONNECTED` / `RO_E_CLOSED`，用进程内向量异常观察器确认这些调用没有产生首次 C++ 异常，同时验证空操作和取消返回状态。测试不修改 VS 异常设置，也未禁用其他异常检查。初始化失败、损坏封面解码或其他未经此适配层处理的错误仍由原异常处理逻辑保护。

补充处理后的 Debug / Release 媒体 UI 回归、媒体服务 fixture 与启停测试均通过。Debug 桌面回归先使用独立输出目录构建的程序，并按 PID 选择测试窗口，避免操作用户正在调试的旧实例；测试完成后，VS 默认的 Debug 输出也重新构建。

VS 对已捕获异常也可中断的行为见 [微软异常调试说明](https://learn.microsoft.com/en-us/visualstudio/debugger/managing-exceptions-with-the-debugger?view=vs-2022)。若仍中断，应查看调用堆栈中的项目代码行及 `result` / HRESULT，而不是只记录 `throw_hresult` 的地址。
